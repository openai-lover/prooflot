# 실행과 지갑 준비

현재 PC에서는 start.ps1을 실행하고 http://127.0.0.1:4317 을 여세요. Python 봇에는 Docker Desktop이 필요합니다. 규칙형과 Python 봇에는 LLM API 키가 필요 없습니다.

첫 방문에는 봇 등록 → 검사 결과 → 구매·다운로드·재시험을 소개하는 약 13초 애니메이션이 나옵니다. 같은 브라우저에서는 다시 자동으로 뜨지 않습니다. 새 소개 화면은 [바로 재생](http://127.0.0.1:4317/?intro=1)하거나, 페이지 하단 **서비스 소개 다시 보기**에서 열 수 있습니다. 일시정지·장면 선택·건너뛰기가 가능합니다.

소개와 메인·봇 등록·검사 결과·구매 화면을 같은 디자인으로 통일했습니다. 소개에서 **마켓 둘러보기**나 **내 봇 등록하기**를 누르면 해당 화면으로 이어집니다. 봇 등록은 파일 업로드와 이름·버전 미리보기 중심이고, 상세 설명은 펼쳐볼 수 있습니다. 구매 창에서는 사용권 가격·저장 예치금·별도 가스비를 구분합니다. 이미 구매한 봇은 **내 봇 보관함**에서 검사 결과를 열거나 내려받고 다시 시험할 수 있습니다.

## 내 지갑으로 사용하기

1. Meteor 또는 Nightly에 **본인 테스트넷 계정**을 준비하세요. 지갑 본화면에서 직접 잠금을 해제합니다. 앱의 **지갑 연결 → 지갑에서 서명**을 누르고 외부 지갑에서 로그인 서명을 확인합니다. 앱에 비밀키·복구 문구를 입력하는 칸은 없습니다.
2. **봇 등록**에서 Python 코드 또는 규칙을 등록합니다. 연결된 지갑이 제작자가 됩니다. 연결 전의 로컬 예제 기록은 별도 체험 기록입니다.
3. **백테스트**에서 BTC 실제 데이터 또는 CSV를 골라 검사합니다. 완료 후 성과와 주의사항을 확인합니다.
4. **판매 등록**에서 0 초과 0.5 test NEAR 이하의 가격을 정합니다. 지갑에서 버전·검사 작업 등록과 판매 등록을 차례로 승인합니다. 초기 예치금은 총 최대 0.08 test NEAR와 가스비이며, 남은 예치금은 지갑 메뉴에서 회수합니다.
5. 구매자는 상품의 검사 결과·공통 시험·버전·제작자 지갑을 보고 **구매 조건 확인 → 지갑으로 구매 → 지갑에서 승인**을 누릅니다. 가격에 저장 공간 예치금 0.02 test NEAR와 가스비가 더해집니다. 외부 지갑의 최종 Approve로 서명합니다.
6. **내 사용권 → 봇 파일 받기**로 ZIP을 받습니다. **다시 테스트**는 구매한 버전과 원래 데이터로 새 Python 프로세스를 실행합니다.
7. 판매자는 상단 지갑 메뉴의 **내 지갑으로 받기**로 판매대금과 남은 예치금을 출금합니다.

모두 테스트 토큰이며 실제 결제가 아닙니다. 상금 수령용 메인넷 지갑과 혼동하지 마세요. 프롬프트 봇의 실제 API 호출 비용은 별개입니다.

Signal Check의 0.01 test NEAR 상품을 확인할 때는 테스트 잔액 0.5로 진행했습니다. 예치금 포함 표시 금액은 0.03이지만, Meteor는 가스비 준비를 포함해 약 0.131의 잔액을 요구해 최초 0.1로는 실패했습니다. 필요한 잔액과 실제 사용한 가스비는 다릅니다. 테스트 토큰을 준비하고 지갑의 잔액 검사를 확인하세요.

‘Continue in Meteor Web’는 별도로 열린 지갑 창의 응답을 기다리는 화면입니다. Meteor 창에서 Connect 또는 서명을 마칩니다. 앱의 로그인 서명 버튼이 나오면 눌러 다음 요청을 여세요. 실패한 요청은 닫고 다시 시도할 수 있으며, 이미 발급된 사용권에는 재결제하지 않습니다.

## 중간에 창을 닫았다면

같은 계정을 다시 연결하세요. **이어서 확인** 알림은 이미 보낸 거래를 최종 체인 상태와 대조합니다. 구매가 기록됐으면 재결제 없이 다운로드를 복구합니다. 판매는 승인하지 않은 단계부터 이어집니다. 알림 숨기기는 이미 승인한 거래를 취소하지 않습니다. 브라우저 저장소를 지웠다면 같은 상품의 구매 버튼으로 기존 사용권을 다시 확인할 수 있습니다.

로그인 서명은 5분 안에 한 번만 사용할 수 있습니다. 세션은 12시간이며, 다운로드·판매·결제 시 키가 여전히 계정의 FullAccess 키인지 최종 블록에서 확인합니다.

## 새 PC와 개발 환경

Node.js 24, Docker 설치 후 npm ci, npm run build, npm start를 실행합니다. 상세 Docker 이미지와 계약 빌드 명령은 README에 있습니다. 테스트넷 운영자 설정이 없는 설치는 로컬 모드로 동작합니다.

실제 새 테스트넷 등록은 Windows에서 npm run testnet:setup으로 **본인의 개발용 계약/운영자**를 준비합니다. 키는 data/testnet-keys.dpapi에 Windows CurrentUser 방식으로 암호화됩니다. 일반 제작자·구매자의 키를 이 파일에 넣지 않습니다. 운영자는 결과 기록·정산만 서명하고, 개인 판매·구매는 외부 지갑이 서명합니다. 공통 시험 예치금은 별도 개발 계정이 부담합니다.

이미 제공된 공개 증거는 지갑·키·서버 없이 검증할 수 있습니다.

~~~sh
node scripts/check-wallet-proof.mjs
node scripts/check-meteor-proof.mjs
node scripts/check-benchmark-proof.mjs docs/wallet-benchmark-evidence.json
~~~

개발자용 전체 실거래 검증: 서버 실행 후 npm run testnet:wallet. 별도 제작자·구매자 테스트 계정을 사용하며 키는 data/wallet-test-keys.dpapi에만 암호화됩니다. 앱 서버는 이 파일을 읽지 않습니다. 이것은 외부 지갑 UI의 사용자 승인 자동화가 아닙니다. 현재 계정으로 구매 ZIP만 재확인하려면 node scripts/verify-wallet-download.mjs를 실행합니다.

## AI 프롬프트 봇을 쓰는 경우만

[NEAR AI Cloud](https://cloud.near.ai)에서 크레딧과 API 키를 준비하고, 자신의 터미널에서 scripts/configure-ai.ps1을 실행하세요. 키는 숨김 입력 후 data/ai-settings.dpapi에 암호화됩니다. 서버 재시작 후 설정한 모델 ID로 프롬프트 봇을 등록합니다. 모델은 매 관측 시점에 매매 판단을 반환합니다.

키를 채팅에 보내지 마세요. 실제 유료 모델 호출과 제공자 과금 상한은 이번 검증에 포함되지 않았습니다. 일반 봇 검사·거래에는 필요 없습니다.
