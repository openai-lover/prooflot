# BotPassport: 공모전 재평가와 개선

확인일: 2026-11-13. 이전 표시 이름 AgentProof. 이 문서는 수상 확률이나 심사위원의 평가를 추정하지 않는다.

## 판단

**실행 가능한 제출용 MVP이며, 개선 전보다 설득력이 높아졌다. 다만 우승권이라고 단정할 근거는 부족하다.** 백테스트와 봇 마켓 자체는 새로운 범주가 아니다. 제품의 제안은 “좋은 성적을 골라 파는 봇” 대신 **동일 버전을 고정된 여러 시험에 넣고, 시작 조건과 전체 결과를 남긴 뒤 그 버전의 사용권을 거래하는 시장**이다.

이번에는 UI 설명만 추가하지 않았다. 실행 전에 NEAR가 조건 해시를 확정하도록 만들고, 4개 공개 시험·실패 이력·실제 Python 실행·무키 체인 확인을 연결했다. 반면 실행 진실성은 운영자를 신뢰하며, 개인 지갑 결제와 독립 제작자·구매자의 실제 사용 증거는 없다. 이 한계를 숨기면 경쟁력이 아니라 신뢰를 잃는다.

## 공식 조건 재확인

- [공식 안내](https://nearhackathon.com/)와 [HACKATHON.md](https://nearhackathon.com/HACKATHON.md): 개발·제출 마감은 2026-11-14 23:59 UTC, 한국 시간 **11월 15일 오전 8:59**. 공개 저장소와 X 시연 게시물 링크가 필요하다.
- 테스트넷만으로 참가 가능하다. NEAR를 실제 사용하는 자체 계약으로 진입할 수 있으며 이 제품에 LLM 호출을 억지로 넣을 필요는 없다. 중심 트랙은 Agent Economy다.
- 로컬 실행만 제공할 경우 설치·실행을 재현할 README와 동작을 보여주는 영상이 중요하다. AI 도구의 실행 검토 뒤 최종 결정은 사람 심사위원이 한다. 공개된 세부 배점표는 확인하지 못했다.
- 공개 배포, X 게시, 최종 신청은 이번 작업에서 수행하지 않았다. 완성된 로컬 제품이 자동으로 제출된 것은 아니다.

## 조사 범위와 경쟁작

[공식 공개 디렉터리 API](https://nearhackathon.com/api/projects?page=1)는 확인 시점에 **899개 항목**을 반환했다. 이는 중복 제거·자격 검증을 마친 참가팀 수가 아니다. 첫 페이지, `backtest`·`bot`·`market`·`agentproof` 검색, 관련 공개 저장소를 표본 조사했다. 전체 899개를 실행하거나 전수 평가하지 않았다. `backtest` 검색 0건은 유사 제품이 없다는 증거가 아니다. 공개 스냅샷은 [contest-directory-snapshot.json](contest-directory-snapshot.json)에 있다.

| 비교 대상 | 확인한 공개 근거 | BotPassport에 주는 기준 |
|---|---|---|
| [Veto](https://github.com/Bronxydrone/Veto) | 공식 디렉터리 등재. README와 테스트·트랜잭션 안내는 에이전트의 지출 제한을 계약과 제한된 키에서 강제하는 구조를 설명한다. | “왜 NEAR인가”가 화면 설명뿐 아니라 실행 제약으로 드러나야 한다. 공통 시험은 FINAL 조건 기록 전에 실행하지 않도록 개선했다. |
| [LeashPay](https://github.com/hassaanraja282-lgtm/leashpay) | 공식 등재. 공개 계약, 권한·승인·환불 흐름, 로컬 재현 절차와 개발 서버 키 보관 한계를 명시한다. | 정상 경로뿐 아니라 거절·실패·복구를 시연해야 한다. 기록 실패, 부분 실행, 중단 이력을 테스트하고 공개했다. |
| [CEOClaw의 AgentProof](https://github.com/CEOClaw/agent-economy-near) | 동일 행사 참가 의사를 밝힌 별개 공개 저장소. README는 서로 다른 소유자의 실제 작업 검사와 NEAR 기록을 제시한다. 공개 디렉터리 검색만으로 제출 완료 여부는 확인하지 못했다. | 우리에게 부족한 것은 독립 사용자들의 실제 사용 근거다. 또한 동명이어서 표시·제출용 이름을 **BotPassport**로 변경했다. |

경쟁 저장소의 실행 횟수·테스트 개수는 해당 작성자의 주장이다. 이번 조사에서 그 테스트를 직접 실행하거나 해당 제품 전체를 보안 감사하지 않았다. 숫자가 많은 제품이 우승한다는 결론도 내리지 않는다. 기존 Solana·Monad 수상작 조사는 [winner-benchmark.ko.md](winner-benchmark.ko.md)에 별도로 남아 있다.

## 실제로 바꾼 부분

| 개선 전 약점 | 구현한 변화 | 남는 한계 |
|---|---|---|
| 72시간·체결 1회 상품 보고서 | BTC·ETH × 2개 고정 기간, 각 168개 실제 캔들. 4개 독립 시험을 새 실행 | 장기·다양한 시장 전체를 대표하지 않으며 공개 과거 데이터라 과적합 가능 |
| 판매자가 고른 결과만 강조 가능 | 공통 시험의 조건 변경·케이스 삭제 API 없음. 모든 시작과 실패를 로컬 공개 이력에 보존 | 운영자가 DB를 통째로 조작하는 것까지 막지는 못함. 온체인 전체 시도 인덱서도 아직 없음 |
| 결과를 만든 뒤 계약에 기록 | 입력·버전·엔진·요청 횟수의 해시를 먼저 FINAL 확정하고 실행, 전체 결과 해시를 다시 기록 | 계약이 실행 시점·실제 계산·성과를 독립적으로 증명하지 않음 |
| 부분 실행도 검사 경고만으로 판매 가능 | 새 제작자 상품 등록은 모든 요청 판단을 마친 결과만 허용 | 기존 불변 보고서와 과거 상품을 소급 수정하지 않음 |
| 심사위원이 로컬 키를 준비해야 체인 점검 | `node scripts/check-benchmark-proof.mjs`로 공개 RPC에서 8개 항목 확인 | 데이터 수집과 Python 실행은 별도 재현 필요 |
| 상품 성과와 검증 상태 혼동 | 공통 검증 페이지, 시도 이력, 4개 성과 카드, 체결 부족 표시, JSON 다운로드 | 안전 점수·수익 보증·독립 인증은 제공하지 않음 |

## 제출에서 주장할 수 있는 것

“Test the bot version you will actually receive. Commit the test conditions first, see every outcome, and buy that exact version on NEAR testnet.”

제작자 코드 → 4개 공통 시험 → 유리하지 않은 결과도 표시 → 온체인 조건·결과 확인 → 동일 버전 사용권 구매 → 다운로드·재시험이 중심 시연이다. ‘우승 확정’, ‘수익 봇 인증’, ‘신뢰 없는 성능 증명’, ‘내 지갑 비수탁 결제’는 현재 구현과 맞지 않는다.

가장 큰 다음 과제는 실제 제작자와 구매자의 사용 증거, 개인 지갑 서명·권한 복구, 공개 시연 영상이다. 제품의 차별성과 기술 근거는 강화했지만 이 항목 없이 상용 준비가 끝났다고 평가하지 않는다.


## 같은 날 후속 구현 — 개인 지갑

이 문서의 초기 평가 이후 개인 지갑 연결·NEP-413 인증·제작자 판매 서명·구매자 결제·지갑별 다운로드와 복구를 구현했다. 별도 테스트 계정으로 실제 거래 흐름 14개를 통과하고 지갑 소유 봇의 4구간 공통 시험도 마쳤다. 이후 사용자가 준비한 nearblog6709.testnet으로 Meteor Web의 실제 로그인 서명·구매·ZIP 다운로드·새 Python 재시험까지 확인했다. 개인 구매자 흐름 16개 대조와 공개 체인 검사 10개가 통과했다. 이전의 “개인 지갑 미구현” 및 “외부 지갑 구매 미검증” 평가는 이 후속 결과로 대체한다. 제작자 지갑 UI·Nightly 확장 승인, 독립 사용자 실증·공개 영상·운영자 실행에 대한 신뢰 문제는 여전히 남는다. 최신 근거는 [completion.ko.md](completion.ko.md)와 [Meteor 증거](meteor-wallet-evidence.json).
